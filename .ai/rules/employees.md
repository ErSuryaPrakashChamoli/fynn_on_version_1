# Employees

## Reporting columns are written only by ReportingLineService
Since 2026-09-15 nothing writes superviser_id/manager_id/cluster_id/business_head_id directly. The Employee form has ONE "Reports To" select (not a column): CreateEmployee::mutateFormDataBeforeCreate() derives the four columns via columnsUnder(); EditEmployee unsets it and calls ReportingLineService::reportTo() in afterSave() (page runs in a DB transaction). The Transfer Employee action, HierarchyReassignmentService::transfer()/reassign() and EmployeeImporter (reports_to emp_id, falling back to legacy superviser_id then manager_id) all go through the same service.

reportTo() validates the boss (active, strictly senior; Business Head/Admin report to nobody; everyone else needs a boss, a Cluster Manager only once a Business Head exists), re-fills every descendant from the tree, never touches reporting_date, and writes a history row for every employee whose columns changed — exited ones too since 2026-11-14 (their cases still disburse after they leave, and ReportingTimeline rebuilds past months from these rows; their exit row is left open). The effective date is what every month figure keys on, so set it to the real date of the move. It always runs on edit save, so saving an employee also tidies drifted columns under them. A designation change is dated with ReportingLineService::recordDesignationChange() (a 'designation' history row) so earlier months keep the old designation. A designation change re-slots the direct reports that stay (reportTo() each one back to the employee, same date) — the tree resolves a boss only through the column matching the boss's designation, so without the re-slot a promoted Team Leader's callers fall through to the old Manager. Done by the importer, a correction on an exited employee's form, and EmployeePositionChangeService (see below). Covered by tests/Feature/ReportingLineChangeTest.php.

## Employee dropdowns come from the Employee Setup lists, never hardcoded arrays
Since 2026-09-28 Designation, Position, Target Category, Cost Center, Unit and Role are admin-managed (sidebar "Employee Setup", Admin only). Models use App\Models\Concerns\IsEmployeeOption: options()/optionsIncluding()/labelFor(), delete blocked while an employee holds the value. Labels are swapped against columns: Designation model -> employees.position (stored by NAME, rename cascades to employees); Position model -> employees.designation (id = DESIGNATION_* code; is_system rows can be renamed, never deleted; admin-added positions have designationRank 0, i.e. outside the reporting tree). TargetCategory/CostCenter/Unit store an immutable generated `code`; the target comes from TargetCategory::targetAmountFor($code, $month) — dated amounts since 2026-11-24 (targets.md), falling back to target_amount, else numeric code. Only callers carry a Target Category. RoleResource::SYSTEM_ROLES are role names checked in code — never renamable/deletable; add to it when code starts checking a new role name. Covered by tests/Feature/EmployeeSetupListsTest.php.

## Employee Setup lists: Active toggle and dependency-aware delete
Since 2026-09-28 every Employee Setup list (and roles) has is_active. Forms offer only active options via optionsIncluding()/activeOptions() (the value already on the record stays selectable); options()/labelFor() still cover inactive ones for display. Delete goes through App\Filament\Actions\DeleteWithDependenciesAction (action name 'delete'): if employees/users still hold the option, the pop-up lists them with Edit links and a required "Move them to" select, then moves them (IsEmployeeOption::moveEmployeesTo / RoleResource::moveUsers) and deletes in one transaction. Move targets: other active options; Position only to out-of-tree positions (rank 0); Role never to hierarchy roles. Test trap: Role's guardable-column list is cached before the is_active migration, so Role::create(['is_active' => false]) drops the flag in tests — use forceFill.

## Work is handed over only on exit; moves and position changes ask only about the team; all are dated
User decision 2026-11-18 (replacing 2026-11-14/16): while an employee stays on the rolls, every customer, lead and assigned lead they hold stays theirs — whoever created it or gave it to them (incl. admin-distributed leads), any position — and delegations run on. Hand-over of work happens ONLY when they leave. EmployeeDependencyService defines "attached": active direct reports, open customers they own (JourneySlaService::activeCustomersQuery on assign_to), open assigned leads and leads (not converted, latest status not in CustomerAssignment::CLOSED_FOLLOW_UP_STATUSES), pending/active delegations. SCOPE_LEAVE (exit) = all of it; SCOPE_MOVE (staying: transfer, reassignment, position change) = direct reports only, and only those not moving along with them. Finished work (disbursed/dropped customers, converted/closed leads) is deliberately NOT handed over — achievement and lead reports credit whoever held it. Hand-overs go through the owning services (ReportingLineService, CustomerReassignmentService, CustomerAssignmentService, CustomerJourneyDelegationService).

Exit hand-over targets: EmployeeDependencyService::newOwnerOptions() = everybody on the rolls but the leaver, any position, grouped by position (searchable select). moveOpenCustomers passes CustomerReassignmentService::reassign(..., anyPosition: true); that service still limits new owners to Manager/Team Leader everywhere else (Customer Reassignments screen). Direct reports still go only to somebody more senior than all of them (newBossOptions).

Leaving: only EmployeeInactivationService::inactivate() (Edit page "Mark Inactive", inactivity-ticket Approve). exit_status on the Employee form is disabled + not dehydrated while active (EditEmployee also unsets it); it can still bring an exited employee back or fix exit_date. exit_date required, never future, never before doj; closes open reporting-history rows and writes the 'exit' row.

Moving (user decision 2026-11-24, replacing "the team never moves"): the admin decides how much of the team goes — whole, part, or none — for anybody at any level (Team Leader, Manager, Cluster Manager…). Everybody, caller or above, takes ALL their open work along — nothing is reassigned; the new boss sees it from the effective date, and past months stay with the old team via the dated history rows. leads.created_by (added 2026-11-16, set by Lead::booted()) is still recorded but decides nothing. Paths, all through EmployeeTransferService:
- transfer($employee, $newBossId, $date, $remarks, $user, $comingAlongIds = [], $stayingBehindBossId = null) — "Transfer Employee" (TransferEmployeeAction, ONE step: New Boss + "Their team" whole/part/none + "Moving with them" checklist + "Those staying behind report to", prefilled with their current boss). Stay-behinds are moved first (moveDirectReports with $comingAlongIds as except, same date), then reportTo() carries whoever is left below. With stay-behinds and no boss it still refuses on 'reports_to' ("still has N direct report…" — the importer's "Move only the employee" and old callers rely on this). The stay-behind boss may not be the employee or anybody below them ('staying_team_boss'); stayingBehindBossOptions() already excludes them.
- moveTeam($boss, ?$memberIds, $newBossId, …) → HierarchyReassignmentService::moveTeam() — "Move Team" (MoveTeamAction 'moveTeam'): the boss stays, all (null) or the ticked direct reports move, each with their subtree. Whole team = on-roll direct reports + exited ones that still have on-roll people below. Logged as transfer_type whole_team / part_team (source/target_cluster_manager_id = the clusters, via clusterOf). Target may not be in the boss's own subtree.
- reassign() — Flexible Reassignment rows carry 'team' (TEAM_WHOLE = comes along, skipped by blockers(); TEAM_NONE/missing = stays behind → clearTransferDependencies hand-over step as before). Splitting a team there = a row per person going elsewhere; rows still run lowest level first.
ListEmployees "Transfer / Reassign Team" modes are ListEmployees::MODE_MOVE_TEAM ('move_team', any boss — replaced the Cluster-Manager-only Full Cluster mode in the UI) and MODE_FLEXIBLE ('flexible_reassignment'). HierarchyReassignmentService::transfer() (full cluster) stays for ReportingLineChangeTest and is no longer reachable from the UI. The Edit form's Reports To (EmployeeResource::moveProblem) still refuses a straight move for somebody with a team and points to "Transfer Employee"; the importer calls transfer() without team args (MOVE_WITH_TEAM uses reportTo()).
Where the actions live: Edit page (Transfer, Move Team, Change Position, Correct Date, Mark Inactive), View page (Transfer, Move Team, Change Position, Correct Date), Employees list row "Move / Promote" group (Admin only, bottom-start), and Employee Lookup "Manage Employee" group (Admin only — EmployeeLookup::manageActions(); actions get ->record($this->employee) and ->after() reloads the page; Mark Inactive reloads only once they have left, because its hand-over step re-opens itself). Covered by tests/Feature/FlexibleTeamMovementTest.php and EmployeeTransferTest.php.

Promotion, demotion and target category change (since 2026-11-16): only EmployeePositionChangeService::change() ("Change Position / Target", ChangeEmployeePositionAction, action name 'changePosition'). Since 2026-11-18 it is ONE step with no dependency step: work is never asked about. When the designation changes and somebody reports to them, the form shows "Their team reports to" (team_boss, options = newBossOptions). Left empty, the team STAYS with them (user decision 2026-11-18) — allowed only while the new position is still senior to every active report (teamCanStay()/teamSeniorRank()); otherwise (a demotion that would strand them) it is required and change() refuses on 'team_boss'. A chosen boss: moveDirectReports() before the position is saved. Staying: child ids are read BEFORE the designation is saved, then each is reportTo()'d back to the employee right after the save and before the employee's own reportTo(), so the team gets one dated row, not a same-day detour through the old boss. A category-only change touches nobody else. The Edit form's Position and Target Category are disabled + not dehydrated while on the rolls (EmployeeResource::isOnTheRolls; EditEmployee also unsets them); exited employees stay editable for corrections. The effective date may not be future, before doj, or before the last recorded line/designation change (designation) or category change (category) — earlier would rewrite that later row.

Effective dates (user decision 2026-11-24, after Punit Kumar ME0201's 1 Nov promotion could not be keyed in): earliestEffectiveDate() ignores line rows that kept the same people above the employee (ReportingLineService::movesEmployee() — e.g. "Follows X's designation change." re-slots and no-op rows); a back-dated designation change deletes such rows on/after its date (dropSupersededLines(), for them and their staying team) so they cannot put the old position's columns back, then resequenceHistory() re-links effective_to. A change keyed in with the wrong date is fixed with "Correct Effective Date" (CorrectPositionChangeDateAction 'correctChangeDate', Edit + View pages) → EmployeePositionChangeService::redateLastChange(): moves the last designation/category change and every row written with it (own rows of that day; team rows of that day remarked "Follows {name}'s designation change." / "Handed over from {name}." / the own line row's remarks naming them) — refused past another real change. The Employee form, the Change Position pop-up and Employee Lookup ("Designation Since") show positionSince()/categorySince(). The View page fills reports_to (it used to show empty for everybody). The Employee import takes an optional effective_date column (blank = upload day) for promotions, demotions and moves, checked like the pop-up's date. Migration 2026_11_24_113213 moved ME0201's promotion to 2026-11-01. Covered by tests/Feature/PositionChangeEffectiveDateTest.php.

Target categories are dated like designations: ReportingLineService::recordCategoryChange() writes a 'target_category' history row (old_category/new_category = employees.category codes); App\Support\TargetCategoryTimeline rebuilds the category held on each day (latest segment = today's employees.category, so a column edited without a row applies from the last recorded change; no rows = today's category for all time, the old behaviour). AchievementCalculatorService::categoryTarget($employee, $monthStart, $monthEnd) splits a month by days when the category changed inside it (user decision 2026-11-16: old amount × days before / days-in-month + new amount × days from); every other month keeps the category held in it. A caller's team target with 10+ days on the rolls is that same (split) category amount — the flat PARTIAL_MONTH_TARGET is gone (2026-11-24). Any new reader of employee_reporting_history that rebuilds reporting lines must skip ReportingLineService::NON_REPORTING_CHANGES. Category AMOUNTS are dated too since 2026-11-24 (target_category_amounts, "New amount applies from" on the edit pop-up — see targets.md); past category changes made before 2026-11-16 left no record (no activity log on Employee) and can't be reconstructed. Covered by tests/Feature/EmployeePositionChangeTest.php.

Mark Inactive and the Flexible Reassignment (rows whose team stays behind) share EmployeeDependencyStep and re-mount via App\Filament\Actions\ReopenAction (Filament keeps a replaced modal open only if name+context differ — hence the 'pass' context counter; assertActionMounted() fails on exact context, assert mountedActions[0]['name'] instead). The Flexible Reassignment hands over through ListEmployees::clearTransferDependenciesAction() (page method action, args employee + batch) and then replaceMountedAction('transferCluster', ['batch' => ...]) refills the form. Covered by tests/Feature/EmployeeInactivationTest.php, EmployeeTransferTest.php and EmployeeSetupInactivationTest.php.

Unit and Cost Center (HasEffectiveInactivation) no longer have an Active toggle: the Inactivate row action moves the holders first, then records `inactive_from` (the first inactive day); a saving hook refuses is_active=false while anyone holds it. Use wasActiveOn()/scopeActiveOn() for date-sensitive figures. Designation/Position/Target Category/Role keep the plain toggle. Date pickers in these pop-ups use maxDate(now()), not today(): the non-native picker fills a default with the current time, which fails a midnight max. Covered by tests/Feature/EmployeeSetupInactivationTest.php.
