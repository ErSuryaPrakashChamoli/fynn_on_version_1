# Ai Customer Records Services

## Assign customers/AI records only through CustomerAssignmentService
Since 2026-09-18 every hand-over (customer_assignment_batches + customer_assignments rows) goes through App\Services\CustomerAssignmentService::assign(ids, employeeId, targetType, assignedBy). It dedupes ids, skips targets that already have an assignment, wraps the batch + rows in one transaction and returns ['assigned','skipped','batch']. Callers: AssignCustomersToUserBulkAction (Customers + Customer Data bulk "Assign to User") and the Customer Data header action "Assign by S. No." (AiCustomerRecordsTable::assignBySerialNumberAction, Admin-only, whereBetween on ai_customer_records.id — the "#" column). Do not create batches/assignments inline in a new action; extend the service instead. Covered by tests/Feature/AiCustomerRecordAssignBySerialNumberTest.php.

## "Unassigned" AI record = no assignment row AND not converted
Since 2026-11-14 AiCustomerRecord::scopeUnassigned() is the definition: customer_id IS NULL and no customer_assignments row. Conversion (CreateCustomer::afterCreate) moves the assignment from ai_customer_record_id to customer_id, so CustomerAssignmentService::assign() also skips AI records whose customer_id is set — before this a converted record looked free and could be handed out again. AiRecordSerialRanges::unassigned() repeats the same rule in raw SQL (gaps-and-islands with ROW_NUMBER(); runs break at taken records and at a template change, not at deleted ids) — keep the two in step. "Assign by S. No." is now a Repeater of From/To/user rows ("Range 1, 2, …"; each row's picker offers only what the rows above left free via AiRecordSerialRanges::without(), a row overlapping one above fails on its from_id, all rows run in one transaction) with the unassigned runs listed on top (resources/views/filament/components/unassigned-serial-ranges.blade.php). "Export Customer Data" (AiCustomerRecordExporter, DataDownloadApproval::protect — lead data) reads the holder via AiCustomerRecord::currentAssignment() (latestAssignment, else convertedAssignment by customer_id) and the latest follow-up via subqueries on ai_customer_record_id OR the converted customer_id. Covered by tests/Feature/AiCustomerRecordAssignBySerialNumberTest.php and AiCustomerRecordExportTest.php.

## Uploads build the template from ticked Data Fields — no hand-made Data Template
User decision 2026-11-23: nobody builds a Data Template (AiDocumentSchema) by hand any more. Templates are still created — records, assignments (Template column) and OCR all read schema_id — but only by CustomerDataImportService from the saved fields in customer_data_fields (CustomerDataField, managed on the Admin "Data Fields" screen, which replaced "Data Templates" in the sidebar; AiDocumentSchemaResource is reachable by URL only). Starter field keys are the canonical AiRecordProspectFields keys plus cibil_score, date_of_birth, company_name — keep new starter fields on canonical keys so prospectValue() finds them. A typed new field reuses a saved field that already answers to the name (CustomerDataField::findOrCreateForLabel / otherFieldNamed), else it is saved for next time.

- AI Documents (OcrDocumentForm + CreateOcrDocument): a drag-to-order tick list of saved fields; the last document's columns come ticked (CustomerDataImportService::documentFieldRows, legacy template columns mapped to saved fields where they match). Order matters: the Python table reader assigns columns BY POSITION, so templateForDocument() keeps the ticked fields in exactly that order, reuses a same-name template only when its keys match in order, otherwise creates "Name (2)". The edit page shows the columns read-only (changing them needs a re-upload). The document name (title) is the template name; storeFileNamesIn('original_name') keeps the real file name.
- Excel/CSV "Import Data" (ImportCustomerDataAction, Admin, on Assigned Leads and Customer Data): file → tick fields (matched by column name, any unmatched column offered as a new field) → optional "assign all to". Columns are matched by name, so order does not matter; re-using a name appends rows and adds missing fields to that template; every column name a field is uploaded from is appended to its aliases. import() is one transaction and throws InvalidArgumentException for user errors. SpreadsheetFile (OpenSpout) reads the first sheet, skips a one-cell title row, returns Excel dates as Y-m-d; .xls is refused. The old template-based CSV ImportAction button was removed from Customer Data (AiCustomerRecordImporter class and its test remain).

Covered by tests/Feature/CustomerDataImportTest.php and AiDocumentColumnPickerTest.php.
